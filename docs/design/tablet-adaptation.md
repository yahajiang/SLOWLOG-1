# 平板适配规格（tablet-adaptation）

> 状态：**已实施（v2 决策版）** · 基线：2026-09-14 · 关联：gallery-DESIGN.md · 依赖响应式修复（0b722b6 / cc459be / 6e18b3c / 07beb02 / 6e18b3c）
>
> **v2 决策（用户定）**：**平板风格同桌面端**——不做移动式抽屉、不做竖屏堆叠；桌面结构原样呈现，
> 只解决「装得下」与「对齐」。此前 v1 提案的目录抽屉 / hero 竖屏堆叠 **废弃**。

## 1. 档位语义（终版）

| 档位 | 视口 | 形态 |
|---|---|---|
| 移动 | <768 | /m 平行树 |
| 平板（桌面风格紧凑） | 768–1535 | 桌面结构原样：70% 容器、侧栏目录 ≥1024、**搜索 <1280 收图标** |
| 桌面满配 | ≥1536 | 格言、内联搜索框、宽间距 |

**关键不变式**：顶栏容器与内容容器同为 70%（对齐）；<1024 阅读页无侧栏目录（宽度不足以并排，桌面行为同理）。

## 3. 各档宽度账（顶栏，70% 容器）

- 768 → 537px 容器：紧凑顶栏（图标搜索）内容 ≈ 458px ✓
- 1080 → 756px：✓（导航单行 + 图标搜索）
- 1366 → 956px：xl 档内联搜索 224px，总 ~660px ✓ 余量充足
- ≥1536 → 1075px+：满配（格言 + 内联搜索）✓

## 4. 明确不做（决策记录）

- 目录抽屉（<1024 无侧栏目录 = 桌面行为；如未来要补，再议）
- hero 竖屏堆叠（保持 `md:flex-row` 并排，92%…——实际保持 70% 容器下 768 即并排）
- 触控目标强制 44（保持桌面 chrome 尺寸 34×30 / 30×30；移动树 /m 已是 44+）
- 相关阅读三列改两列（保持桌面栅格）
